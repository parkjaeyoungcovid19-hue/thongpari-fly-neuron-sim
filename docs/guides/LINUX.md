# Linux desktop

The Linux entry point is `./run_linux.sh`. It opens a **native PySide6/Qt desktop
window**, computes the full shipped FlyWire brain on CPU, and starts an owned
FlyGym/MuJoCo body process on private loopback ports. The macOS Swift/Metal app
and its launchers keep their existing implementation.

## Install and launch

Use Python **3.12** on an x86_64 Linux desktop. The tested cloud setup uses
FlyGym 2.1.0, MuJoCo 3.9.0, NumPy 2.5.4, Numba 0.68.0 and PySide6 6.10.2.
A display session and the usual Mesa EGL/OpenGL and Qt X11 runtime libraries
are needed. The cloud environment already has these libraries. For a fresh
Ubuntu 24.04 installation:

```sh
sudo apt-get install python3.12-venv libegl1 libgl1 libxkbcommon-x11-0 \
  libxcb-cursor0 libxcb-icccm4 libxcb-keysyms1 libxcb-render-util0 \
  libxcb-xinerama0 libxcb-xkb1
./setup_linux.sh
./run_linux.sh
```

If Python 3.12 has a different path, run
`THONGPARI_PYTHON=/path/to/python3.12 ./setup_linux.sh`.
No CUDA, Docker or external API credentials are required. Package installation
uses normal TLS verification. Launching requires no Internet access.

```sh
./run_linux.sh --mock            # full CPU brain, kinematic body and top-down diagram
./run_linux.sh --seed 0x1234     # reproducible uint32 neural seed
```

The first launch compiles Numba kernels and prewarms the real body. The window
shows progress and enables controls after the backend handshake. Startup
errors include the location of the backend log. The app checks the shipped
connectome's file sizes, SHA-256 digests and CSR structure before using it.

## Controls and capabilities

| Area | Linux implementation |
| --- | --- |
| World view | MuJoCo's actual RGB render of the live NeuroMechFly scene; right-drag to orbit, wheel to zoom |
| Observe / Participate / Edit | Switch from the toolbar; click objects in Edit mode to select through the backend's ray picker |
| Participant | Click the canvas, WASD movement, mouse look; E grabs/places, G equips the BB gun, F fires; Esc/focus loss releases control |
| World editor | Boxes, spheres, walls, ramps, food, cars, traps; select by list or ray; move, rotate, resize and tilt through backend descriptors and revision-checked edits; duplicate/delete |
| Environment | Applied temperature, mode, continuous wind with independent physical/sensory flags, per-eye covers, flash and body-part touch |
| Brain | All 139,255 neuron positions in a rotatable point cloud; spike highlights; select by click and inspect FlyWire ID/type/role; stimulate one neuron or an identified population |
| Data | Simulated body measurements, population firing rates, source state and sim/wall ratio; hunger explicitly unsupported |
| Experiment | Seeded deterministic brain/body stepping, pause/resume, neural trials, physical wind/loom trials, CSV recording with trial markers |
| Lifetime | Private backend/render ports; quit stops only this app's backend; parent watchdog handles an unexpected app exit |

Physical and sensory interventions use the existing production Python world.
For example, food taste is generated by real proboscis contact; odor has no
route to the identified sugar GRNs. The renderer follows the same model/data
as physics. The mock view is explicitly labeled and does not claim real
MuJoCo rendering.

Edits are acknowledged by the backend. Invalid/stale edits are shown as errors;
the UI does not pretend an unacknowledged request was applied. While paused,
world commands wait until the next resumed simulation quantum. CSV recording
creates a new file; choose a new name if a file already exists.

## Simulation contract and limits

`desktop_lab/brain.py` ports `Sources/Brain/LIF.metal`, `MetalSim.swift`'s parameter/group
configuration, `SensoryModel.swift` and `MotorReadout.swift`. It uses all
15,091,983 edges, PCG noise, float32 membranes, fixed-point integer synaptic
accumulation, the 4 ms inhibitory ring, and 1 ms neural ticks. LLVM may contract
float32 multiply/add into FMA; reassociation is disabled. The full brain is
never replaced by a procedural movement script.

The client uses the existing V4 deterministic protocol: exactly 20 neural
ticks precede each exact 20 ms body quantum. Waiting on a slow CPU/render does
not skip ticks or advance physics independently. Pause stops both timelines.
Reset starts a fresh brain/body timeline and preserves current world objects.

This CPU port is **not validated as bit-identical to Apple Metal**. Gait sine
and compiler rounding can diverge in this chaotic spiking network. Independent
scalar-oracle, fixed-point, RNG, whole-graph, seed/reset and actual looming→GF
checks cover Linux correctness; they do not replace the macOS GPU comparison.
On the cloud CPU a warmed standalone 1 s brain calculation took about 0.77 s;
the integrated software-rendered body is slower than real time. The live
sim/wall metric reports that limit. No Linux GPU compute backend is included.

The Linux and Windows windows share bilingual labels and numerical property
editing. They do not duplicate macOS-native menu-bar overlays, editor drag
handles, pointer-lock preferences, activity-card layout or CSV simulation
replay. V6.6 undo, V6.7 scene-file controls and V7.2–V7.5 exact neural
observation/group/event-window panels remain macOS-only UI features. Recorded
CSV remains available for analysis. These UI differences do not change the
reused physics/world backend. Wayland and physical GPU rendering were not independently
validated; X11/xcb and Mesa EGL were.

## Validate

From the checkout:

```sh
export MUJOCO_GL=egl PYOPENGL_PLATFORM=egl
./flygym-venv/bin/python -m unittest desktop_lab.tests.test_brain desktop_lab.tests.test_session desktop_lab.tests.test_process_lifetime -v
./flygym-venv/bin/python -m unittest desktop_lab.tests.test_desktop -v
./flygym-venv/bin/python flygym_bridge/tests/real/test_lab_real.py
./flygym-venv/bin/python flygym_bridge/tests/real/test_vision_real.py
./flygym-venv/bin/python tools/verify_data.py --no-parquet
```

The desktop test requires a display; in CI run it with `xvfb-run -a`, or set
`QT_QPA_PLATFORM=offscreen` to test Qt without a display. Its real-body checks
require rendered MuJoCo frames, advancing full-brain/body time, a ramp edit and
duplicate/delete, temperature ACK, native key movement, quaternion look,
pause/resume, CSV contents and backend shutdown. `TEST_ARTIFACT_DIR` optionally
saves a window screenshot. CPU and protocol tests include an independent
scalar oracle and a rejected stale revision. `--no-parquet` validates shipped
data but intentionally skips upstream source-parquet reconciliation.

The cloud setup draft records dependency installation and startup instructions.
Publishing through environment settings snapshots installed files, not running
processes. Future tasks use the existing isolated checkout without creating a
worktree unless explicitly requested. A cloud shell without a desktop display
can run the tests and backend; interactive GUI use needs a Linux desktop or a
remote desktop session.

Backend logs are stored in `$XDG_CACHE_HOME/ThongpariFlyNeuronSim/` or
`~/.cache/ThongpariFlyNeuronSim/`. The process watchdog uses a Linux pidfd
where available, so an app crash stops its backend even if a PID is reused.
The Windows client uses [native Windows defaults](WINDOWS.md) for graphics,
logs and process cleanup.
