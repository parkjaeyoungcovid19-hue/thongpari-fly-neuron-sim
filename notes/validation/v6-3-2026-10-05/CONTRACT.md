# V6.3 small implementation contract

- Edit mode only; backend snapshot/pick or the authoritative object list chooses the target. World axes: X/Y ground, Z up; distances mm, yaw degrees about Z. No pitch/roll support.
- Outline and labeled axis handles are an AppKit overlay above the primary MuJoCo image and SceneKit fallback, projected using the same z-up forward/FOV camera as the render stream. Handles edit move XYZ, yaw Z, and descriptor-supported size (XYZ box/wall; one scalar diameter/length for sphere/food/car/trap). Camera gestures outside handles remain unchanged.
- Drag creates a visibly pending draft only, and release submits exactly one descriptor-validated edit_property with captured object revision. Numeric fields + Apply/Return provide equivalent keyboard access; malformed/out-of-range values fail inline, never clamp locally.
- Applied geometry/value comes only from owner snapshots and matching edit ACK (command ID, connection generation, session/epoch, applied tick). One pending mutation; disable controls while pending; stale/malformed/timeout results never claim applied. Identity/mode/selection changes cancel local drafts, not already-sent commands.
- Duplicate/delete use edit_object {schema_version:1, operation:duplicate|delete, target_id, expected_revision}. Backend validates all fields, target/held state/revision before mutation; duplicate keeps shape/size/yaw/food variant at the same position with a generated ID and resets active toy/feeding state. Deliberate overlap is explained in UI. Delete removes actual collision/visual geometry. Legacy delete/move commands remain compatible.
- Both object operations return edit-shaped ACK detail (property_id object.duplicate/object.delete, target_id original ID, actual_value generated/removed ID, revision authoritative world revision). Neither UI selects a duplicate nor clears a deletion before confirmed owner response. All failures are no-mutation.
- Real camera/image transport is asynchronous and currently untagged: outline uses latest owner snapshot/current requested camera, so transient lag may occur during camera motion. Not a pixel-depth occlusion mask.
- No undo/persistence/global environment panels, installs, GUI input or packaging in this stage.
